# Two doors, Claude Code only

Date: 2026-10-13
Decided by: the owner
Related: `2026-10-13-archive-branches-and-v010-re-cut.md` in the eidolon repository.
That record covers archiving the old branches and re-cutting v0.1.0. This one covers
what the re-cut Hearth ships.

## Decision

Hearth ships two doors and supports Claude Code only.

- The novice door is a copy of `skills/` into `.claude/skills`. It is pure PowerShell on
  Windows (`welcome.ps1`, started by `Start Here.cmd`) and pure bash on macOS
  (`macos/Welcome.command`). It has no Node, no hooks, no third-party tools and no cards.
- The operator door is the Node terminal picker, `scripts/welcome.mjs`, started by
  `Operator Setup.cmd` or `macos/Operator Setup.command`. It wires project hooks through
  the bundled installer and needs Node 22 or newer.

The WPF window, the macOS app and the browser installer are removed. Second-host support and
the optional tool cards are removed.

## Why

- A nervous first-time user should not have to install a runtime to get two skills. The
  novice door needs only what the machine already has.
- Hooks need Node. Only people who want hooks should be asked to install it, so that
  requirement lives on the operator door alone.
- The graphical installers could not be shown to work by the automated tests. Their
  windows needed a hand run on real machines, and there were three of them.
- Every extra host and every offered tool widened what Hearth had to verify and keep
  honest. Two skills for one host is a surface that a few checks can cover.

## What keeps the novice door honest

`tests/novice-door.test.mjs` fails if either novice script contains the word node, if the
PowerShell parser reports an error, if `bash -n` fails, or if a copy into a temp folder
differs from `skills/`. CI repeats the Node check with `grep -iw`.

## Consequences

- The macOS doors run for real in the test suite wherever bash exists; GitHub's macOS runner
  ran them on 2026-10-13 (copy, skip, replace with backup, the operator handoff), as did WSL
  Ubuntu. A run on a user's own Mac is still to be recorded.
- `skills/` and `vendor-lock.json` are regenerated from pinned commits, not edited here.
- The operator door passes `vendor-lock.json` to the bundled installer, so a bundle that
  drifts from its pins is refused before any plan is shown.
- Hearth has no `AGENTS.md`. Claude Code reads only `CLAUDE.md`, which carries the
  maintenance rules itself.
- The second host and the graphical installers are not available in v0.1.0.
